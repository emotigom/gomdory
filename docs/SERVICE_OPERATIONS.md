# 서비스 운영·장애 대응·백업 정책 v1

## A. 문서 목적
이 문서는 교사/학교/기관 검토를 위해 곰도리의 현재 서비스 운영 상태를 요약한 공개 v1 문서입니다.
본 문서는 정식 SLA 계약서가 아니며, 별도 서면 합의가 없는 한 계약상 SLA 보장을 제공하지 않습니다.
기관 계약/유료 플랜 기반의 정식 SLA·계약 조항 문서는 준비 중입니다.

## B. 현재 운영 원칙
현재 운영 기준은 다음과 같습니다.

- 수업 연속성: 수업 중단을 줄이기 위해 핵심 수업 흐름의 안정성을 우선합니다.
- 투명한 커뮤니케이션: 장애/점검 관련 사실을 확인 가능한 범위에서 안내합니다.
- 데이터 최소화: 공식 수업 템플릿은 직접 식별정보 입력 요구를 지양합니다.
- 권한 분리: 교사/게스트 권한을 분리해 운영합니다.
- 서버사이드 학생 코드 미실행: 학생 코드는 서버에서 실행하지 않습니다.
- 예방/복구 개선: 장애 예방 및 복구 절차는 운영 경험을 반영해 지속적으로 개선 중입니다.

## C. 지원 및 문의
현재 공개 문서 기준으로 운영 문의는 학교·기관 도입 경로를 통해 접수합니다.

- 학교·기관 도입 문의: `/dashboard/billing/institution`
- 공개 안내 페이지: `/school`

공식 지원 채널(전용 이메일/전화/티켓 시스템) 단일화는 준비 중입니다.

## D. 장애 대응 흐름
아래 흐름은 현재 운영 초안이며, 결과 시간을 보장하는 계약 문구가 아닙니다.

1. 장애 인지: 모니터링/제보를 통해 이상 징후를 인지합니다.
2. 영향 범위 확인: 수업 진행, 로그인, 보드/활동 기능 영향 범위를 우선 파악합니다.
3. 임시 조치 또는 우회 안내: 수업 지속을 위한 임시 조치 또는 우회 사용 방법을 안내합니다.
4. 원인 분석: 재현 정보와 로그를 기반으로 기술 원인을 분석합니다.
5. 재발 방지 항목 정리: 수정 사항과 후속 개선 항목을 정리합니다.

운영 목표는 수업 연속성 회복과 투명한 상황 공유이며, 세부 대응 템플릿은 준비 중입니다.

## E. 점검/유지보수 안내
- 정기 점검 사전 안내 정책은 준비 중입니다.
- 보안/안정성 이슈 대응을 위해 긴급 점검이 발생할 수 있습니다.
- 정식 SLA가 없는 현재 단계에서는, 중요 수업의 경우 교사가 대체 활동(오프라인/보조 과제 등)을 함께 준비하는 운영 기준을 권장합니다.

## F. 백업/복구 상태
현재 공개 문서 기준으로 정식 백업/복구 정책 문서는 준비 중입니다.
운영 데이터 보관·삭제·복구 기준은 기관 도입 문서 v2에서 구체화 예정입니다.

현재 문서에서는 특정 백업 주기, 보관 일수, point-in-time recovery, RTO/RPO 수치를 보장하지 않습니다.

## G. SLA 상태
현재 공개 SLA 보장은 제공하지 않습니다.
기관 계약 또는 유료 플랜 도입 시 SLA 정책을 별도 문서화할 예정입니다.

## H. 알려진 운영 한계
- 공개 SLA 보장 문서는 아직 없습니다.
- 공개 상태 페이지(status page)는 아직 없습니다.
- 외부 보안감사 통과 증빙은 아직 공개되어 있지 않습니다.
- 표준 incident report 템플릿은 준비 중입니다.
- 백업/보관/복구 세부 정책 확정본은 준비 중입니다.

4. 서비스 상태 페이지 구축
5. 기관 계약용 SLA 초안 문서화
